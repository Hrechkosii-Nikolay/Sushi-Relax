# Приймальна перевірка Sushi Relax

Перед перевіркою заповніть тестові ціни, графік і секрети в безпечному локальному середовищі. Не використовуйте реальні персональні дані.

## Автоматичні перевірки

```bash
find app public scripts config -name '*.php' -print0 | xargs -0 -n1 php -l
node --check public/assets/js/app.js
node --check public/assets/js/checkout.js
node --check public/assets/js/admin.js
php scripts/build-home.php
php scripts/backup.php
```

## Основний сайт і QR-меню

- Перевірити вертикальні категорії, акордеон, пошук і мобільну верстку.
- Перейти з адмінки за посиланням конкретного товару: його категорія має розкритися, а картка - опинитися у фокусі перегляду.
- Переконатися, що прихований товар відсутній на головній, у пошуку та QR-меню.
- Переконатися, що `/qr-menu/` не містить кошика, кнопок додавання й checkout.
- Відкрити статичний `public/index.html` напряму та перевірити стилі й фотографії.

## Кошик і checkout

- Додати однаковий товар із різними опціями: мають утворитися окремі рядки.
- Перезавантажити сторінку: кошик, ім’я й телефон мають зберегтися, адреса - ні.
- Перевірити лічильник у картці, зміну кількості в кошику, ваги, акційної ціни, промокоду, подарунка й доставки.
- Без налаштованого тарифу доставки має бути доступний лише самовивіз.
- Для вихідного дня або дати без слотів кнопка надсилання має залишатися заблокованою.
- Підробити ціну або ID у браузері: сервер повинен відхилити замовлення чи перерахувати його за JSON-каталогом.

## Telegram та повторне надсилання

- При успішній відповіді Telegram має надійти одне повідомлення, а сторінка успіху - показати номер і копію замовлення.
- При явній помилці Telegram кошик не очищається і дозволяється повторна спроба.
- При невизначеній мережевій відповіді повторне натискання з тим самим вмістом не повинно створювати нове замовлення.
- Повторний запит уже доставленого замовлення з тим самим ID має повернути попередній номер без другого повідомлення.

## Адмінпанель і безпека

- Перевірити вхід, ліміт невдалих спроб, CSRF та вихід із сесії.
- Створити прихований товар, завантажити фото, заповнити дані та ввімкнути показ.
- Перевірити опції, рекомендації, акції, промокоди, подарунок, банери, графік і винятки.
- Завантаження скрипту замість зображення або файлу понад 8 МБ має бути відхилене.
- Створити резервну копію, змінити тестове значення й відновити копію з підтвердженням `ВІДНОВИТИ`.
- Архівувати тестовий товар, відновити його, потім повторно архівувати й остаточно видалити з підтвердженням `ВИДАЛИТИ`; перевірити автоматичну копію.
- Спричинити тестову помилку Telegram і перевірити `var/logs/technical.log`: там має бути лише технічний код без імені, телефону, адреси, тексту замовлення чи секретів.
- Перевірити, що `data/`, `var/`, конфігурація й резервні копії недоступні через HTTP.

## Production

- Перевірити HTTPS, Secure/HttpOnly/SameSite cookies, CSP та інші security headers.
- Перевірити права каталогів і реальне виконання щоденного cron резервування.
- Після введення домену перевірити canonical, JSON-LD, `sitemap.xml` і `robots.txt`.
- Провести тестове замовлення через реального Telegram-бота й приватний канал.
