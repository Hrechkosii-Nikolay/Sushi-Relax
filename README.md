# Sushi Relax

Адаптивний україномовний сайт ресторану на HTML5, CSS3 і JavaScript. PHP 8.1+ використовується тільки для серверних функцій, без бази даних та сторонніх frontend-залежностей.

## Що вже працює

- окремий статичний файл `public/index.html` з вертикальним акордеон-меню, пошуком і 32 оптимізованими фото;
- один JSON-каталог для основного сайту та `/qr-menu/`;
- QR-меню лише для перегляду - без кошика та оформлення;
- лічильник кількості в картці, bottom-sheet кошик у `localStorage`, зміна кількості й серверний повторний розрахунок;
- форма доставки/самовивозу, пам’ять імені й телефону (адреса не зберігається);
- PHP-обробник із валідацією каталогу, honeypot, простим rate limit, request ID та відправкою одного plain-text повідомлення в Telegram;
- адаптивна адмінпанель `/admin/` для повних даних товарів, категорій, контактів, текстів, доставки, графіка й винятків;
- створення, архівування, відновлення та підтверджене остаточне видалення товарів; безпечне завантаження JPEG/PNG/WebP із перекодуванням у WebP;
- акційні ціни з періодом дії, додаткові опції та рекомендовані товари;
- окремі рядки кошика для однакових товарів із різними опціями, редагування опцій прямо в кошику та повторна серверна перевірка їхніх цін;
- відсоткові й фіксовані промокоди, мінімальна сума, строки дії та кероване суміщення з акційними цінами;
- структуровані форми промокодів і банерів в адмінпанелі з додаванням, редагуванням та видаленням без службових текстових форматів;
- структуроване керування додатковими опціями товарів і пошуковий список рекомендацій із звичайними прапорцями замість незручного multiple-select;
- доступне меню дій біля телефону («Зателефонувати» / «Написати в Telegram») та фактичний тижневий графік на сторінці контактів;
- захищена сторінка готовності сервера в адмінпанелі: PHP, розширення, права запису, webroot, HTTPS, приховані PHP-помилки, секрети, домен і нагадування про cron;
- узгоджені security headers для PHP і статичного HTML, кешування CSS/JS/зображень та заборона виконуваних файлів у `public/assets/`;
- подарунок за налаштованим порогом до або після знижки;
- до двох банерів головної та автоматична вітрина товарів з активною акційною ціною;
- автоматичне оновлення цін, акцій, банерів і статусу приймання замовлень через API без ручного перезбирання відкритої сторінки;
- canonical, Open Graph, структуровані дані ресторану, `sitemap.xml` і посилання в `robots.txt` після введення реального HTTPS-домену;
- доступний кошик-діалог із поверненням фокусу, його утриманням усередині та ізоляцією фонового вмісту;
- єдиний серверний розрахунок `/api/quote.php` для checkout і фінального замовлення;
- створення, перевірка, ротація та кероване відновлення резервних копій з адмінпанелі;
- файловий rate limit і атомарне резервування idempotency ID для захисту від повторних заявок;
- повторне використання ID того самого замовлення, короткоживучий статус доставки без персональних даних і безпечне повернення вже підтвердженого результату;
- часові слоти, які генеруються сервером за графіком Europe/Kyiv і повторно перевіряються при надсиланні;
- часові інтервали замість неоднозначного одиночного часу та блокування кнопки, якщо на дату немає доступного інтервалу;
- безпечний режим доставки: до введення мінімальної суми й тарифу доступний лише самовивіз, тому відсутня вартість не видається за безкоштовну доставку;
- атомарний запис JSON, резервні копії з перевіркою та ротацією;
- службові сторінки, security headers, адаптивність і базова доступність;
- обмежений приватний технічний журнал без текстів замовлень, контактів і секретів; ротація виконується автоматично.

Назви та фото взято з наданих файлів. Адресу, телефон і графік внесено з офіційного Instagram-профілю `@sushi_relax`. За вказівкою власника для всіх позицій тимчасово встановлено ціну 100 грн. Склад, вагу, час і правила доставки не вигадано: непідтверджені значення залишені порожніми, а онлайн-замовлення вимкнено до повного налаштування.

## Локальний запуск

Потрібен PHP 8.1+ з `curl`, `fileinfo`, `gd`, `json`, `mbstring`, `openssl`. Для фото налаштуйте `upload_max_filesize` і `post_max_size` не нижче 8 МБ.

```bash
php -S 127.0.0.1:8080 -t public
```

Відкрити `http://127.0.0.1:8080`. Для перевірки адмінки створіть хеш пароля й передайте його змінною середовища:

```bash
php -r "echo password_hash('ВАШ_НАДІЙНИЙ_ПАРОЛЬ', PASSWORD_DEFAULT), PHP_EOL;"
SUSHI_ADMIN_PASSWORD_HASH='отриманий_хеш' php -S 127.0.0.1:8080 -t public
```

Не додавайте пароль або хеш у Git.

## Telegram і замовлення

Секрети задаються змінними середовища або у приватному `config/secrets.php` (скопіюйте `config/secrets.example.php`; файл уже виключено з Git):

```text
SUSHI_TELEGRAM_BOT_TOKEN=...
SUSHI_TELEGRAM_CHAT_ID=...
SUSHI_ADMIN_PASSWORD_HASH=...
```

Після цього заповніть ціни й правила доставки та встановіть `orders.manual_enabled` у `data/settings.json` в `true`. Графік закладу і години приймання замовлень уже внесені з офіційного профілю. До повного налаштування кнопка надсилання навмисно заблокована. Telegram-бот має бути адміністратором приватного каналу з правом публікації.

## Структура

- `public/` - єдиний webroot;
- `public/*.html` - готові публічні сторінки: головна, оформлення, доставка, контакти, про заклад, політика та сторінка успіху;
- `public/products/*.html` - окремі статичні сторінки всіх позицій меню;
- `public/qr-menu/index.html` - статичне QR-меню;
- `public/api/*.php` - серверні обробники розрахунку, слотів, Telegram-заявок і динамічних даних;
- `public/admin/index.php` - захищена адмінпанель;
- `app/` - спільна серверна логіка та PHP-шаблони, з яких збираються публічні HTML-файли;
- `data/` - каталог і налаштування, мають бути поза webroot;
- `var/runtime/` - короткоживучі технічні файли;
- `var/logs/` - приватний обмежений журнал технічних кодів помилок без персональних даних;
- `var/backups/` - приватні резервні копії;
- `scripts/backup.php` - створення перевіреної копії та зберігання останніх 30;
- `scripts/build-home.php` - повторне формування всіх публічних HTML-сторінок із JSON-каталогу й налаштувань;
- `config/secrets.example.php` - лише перелік потрібних секретів, без значень.

## Fornex / production

1. Перевірити в панелі хостингу PHP 8.1+, HTTPS, cron і перелічені розширення.
2. Завантажити проєкт так, щоб домен дивився саме в `public/`. `data`, `var`, `app`, `config` і `scripts` не мають бути доступні через HTTP.
3. Надати PHP-користувачу читання `data/`, запис у `data/`, `var/runtime/`, `var/logs/`, `var/backups/`; рекомендовано каталоги `0750`, файли `0640`.
4. Передати секрети через механізм змінних середовища хостингу або приватну конфігурацію поза webroot.
5. Налаштувати щоденний cron, наприклад: `php /ABSOLUTE_PATH/scripts/backup.php`.
6. В адмінпанелі вказати фінальну HTTPS-адресу сайту - після збереження автоматично створяться canonical, `sitemap.xml`, JSON-LD та директива Sitemap у `robots.txt`.
7. За бажанням винести копії ще вище за каталог проєкту через `SUSHI_BACKUP_DIR`.
8. Перевірити HTTPS, cookies, прямий HTTP-доступ до приватних шляхів і реальне створення cron-копії.

Після завантаження відкрийте в адмінпанелі розділ **«Сервер»**. Він не показує значень секретів, але підсвічує відсутні розширення, неправильний webroot, права каталогів та інші типові проблеми конфігурації. Перевірка cron залишається ручною: сайт не позначає її успішною без фактичного запуску на Fornex.

## Перевірки

Повний ручний чекліст міститься у [`TESTING.md`](TESTING.md).

```bash
find app public scripts config -name '*.php' -print0 | xargs -0 -n1 php -l
php -r "json_decode(file_get_contents('data/catalog.json'), true, 32, JSON_THROW_ON_ERROR); json_decode(file_get_contents('data/settings.json'), true, 32, JSON_THROW_ON_ERROR); echo 'JSON OK', PHP_EOL;"
php scripts/build-home.php
php scripts/backup.php
```

Публічні сторінки вже збережені як HTML і не потребують PHP для відображення. PHP залишається лише для API, Telegram-відправлення, адмінпанелі та генерації HTML. Джерелом товарів залишається `data/catalog.json`: після редагування через адмінпанель HTML оновлюється автоматично. Після ручного редагування JSON запустіть `php scripts/build-home.php`.

Для приймального тесту окремо перевірити мобільний bottom sheet, клавіатурну навігацію, пошук, приховання недоступного товару, збереження кошика, серверне відхилення підробленої ціни, помилку Telegram без очищення кошика і відсутність замовлення в QR-меню.

Відновлення доступне в адмінпанелі. Воно приймає лише перевірені файли з приватного каталогу, блокує path traversal, вимагає введення `ВІДНОВИТИ` і перед записом автоматично створює копію поточного стану. Остаточне видалення архівного товару так само потребує явного слова `ВИДАЛИТИ` та автоматично створює резервну копію.
