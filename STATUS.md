# Статус реалізації

## Виконано

- Фундамент без БД, окремий `public/index.html`, спільний файловий каталог і темна адаптивна дизайн-система.
- Головна, меню, QR-меню, доставка, про нас, контакти, checkout, success, privacy.
- Усі клієнтські сторінки переведено на `.html`; PHP у публічному каталозі залишено лише для API та адмінпанелі. Для 32 позицій меню автоматично генеруються окремі HTML-сторінки.
- Пошук, вертикальний акордеон, 32 фото у WebP, lazy loading.
- LocalStorage-кошик, серверне звіряння ID/ціни/наявності, базова Telegram-відправка.
- Авторизація адмінки, CSRF, редагування назви, категорії, опису, складу, ціни, ваги, часу, порядку, мітки й наявності.
- Редагування контактів, текстів, правил доставки, графіка, винятків і параметрів часових слотів.
- Серверна генерація та повторна перевірка доступних часових слотів за графіком Europe/Kyiv.
- Створення, перейменування, сортування та контрольоване видалення категорій.
- Додавання, архівування й відновлення товарів; перевірка MIME/розміру та безпечне перекодування фото у WebP.
- Контрольоване остаточне видалення архівного товару з підтвердженням, резервною копією та очищенням пов’язаних правил.
- Акційна ціна з датами, додаткові опції товару й ручні рекомендації.
- Різні конфігурації опцій як окремі рядки кошика; серверне звіряння ID та цін опцій.
- Блок рекомендацій у кошику без модальних вікон.
- Промокоди: відсоток/фіксована сума, мінімальний чек, строки дії, активність і правило суміщення з акціями.
- Подарунок за порогом до/після знижки з перевіркою доступності товару.
- До двох банерів і окрема вітрина активних акцій на головній.
- Єдиний PHP-розрахунок суми, опцій, знижки, подарунка й доставки для preview та Telegram-замовлення.
- Атомарні JSON-записи й перевірювані резервні копії з ротацією.
- Створення та контрольоване відновлення копій в адмінпанелі; автоматична копія перед відновленням.
- Файловий rate limit для входу й заявок, атомарний idempotency lock і очищення короткоживучих технічних файлів.
- Динамічне оновлення акційних цін, банерів, акційної вітрини та статусу замовлень через окремий read-only API.
- Доступний кошик-діалог: focus trap, повернення фокусу, `aria-modal`, live-лічильник та ізоляція фонового контенту.
- SEO-поля для фінального HTTPS-домену, canonical, Open Graph, JSON-LD ресторану й автоматична генерація sitemap/robots.
- Структуровані CRUD-форми промокодів і банерів замість технічного формату з роздільниками.
- Структуровані рядки додаткових опцій товару та пошуковий checkbox-вибір рекомендованих позицій.
- Контактне меню дій для телефону, валідація публічного Telegram-посилання та виведення тижневого графіка.
- Персистентний у межах спроби request ID, статус idempotency без персональних даних і повторне повернення вже підтвердженого замовлення.
- Серверна перевірка згоди з політикою, часові інтервали та блокування надсилання без доступних слотів.
- Безпечний режим «доставка не налаштована» без неявної обіцянки нульової вартості.
- Захищена production-діагностика PHP, розширень, прав, webroot, HTTPS, секретів, SEO та cron в адмінпанелі.
- Apache security headers, кешування статичних ресурсів і заборона виконуваних файлів у каталозі assets.
- Лічильник кількості безпосередньо в картці, розкриття категорії за deep-link товару та компактний блок закладу/доставки/контактів на головній.
- Приватний ротований журнал технічних кодів помилок без персональних даних і секретів.
- Підтверджені офіційним Instagram-профілем адреса, місто, телефон, графік роботи, години приймання замовлень і посилання на профіль; ці дані виведені на головній, сторінці контактів і в підвалі.
- Окремий графік роботи закладу та інтервал приймання замовлень, який обмежує майбутні часові слоти до 21:00.
- Покрокове оформлення «отримання → контакти й час → перевірка», статичний `checkout.html` для Live Server і автоматичний резервний сценарій із копіюванням замовлення, дзвінком або переходом в Instagram, коли PHP API недоступний.
- Правильний порядок підключення спільного JavaScript та скриптів checkout/success на PHP-сторінках.

## Потребує зовнішніх даних або production-середовища

- Введення фінального домену й перевірка згенерованих SEO-URL; юридичне погодження політики.
- Реальний production-аудит Fornex, cron, HTTPS, прав і Telegram end-to-end.
- Підтверджені правила й тарифи доставки, Telegram-контакт та повні дані каталогу (ціни, вага, склад і час приготування). Публічний опис профілю підтверджує контакти й графік, але не містить цих даних; непов’язані заклади не використовувалися.

За невизначеної мережевої відповіді Telegram короткоживучий idempotency-запис блокує негайний дубль і не містить персональних даних. Exactly-once без зовнішньої стійкої черги не заявляється, як і вимагає ТЗ.

## Перевірено локально 20.10.2026

- PHP-lint усіх PHP-файлів, синтаксис чотирьох JS-файлів і валідність обох JSON-файлів.
- Повторна збірка статичного `index.html`, створення й перевірка резервної копії.
- Серверні розрахунки ціни, копійок, опцій, подарунка, доставки та відхилення невідомого товару.
- HTTP smoke-test головної, QR-меню, службових сторінок, адмінки та read-only API на локальному PHP-сервері.
- Перевірка, що QR-меню не містить елементів замовлення, а головна містить лічильник товару й інформаційні блоки.

Сайт не слід вважати production-ready, доки не заповнені бізнес-дані та не пройдені всі приймальні тести з ТЗ.
